# 交付面：`present`、报告与最终声明

> 先读 `contract.md` 的 L0。本文件只回答一件事：**这次做完的东西，用户怎么拿到。**

## 1. 交付判定（收尾轮，Lead 做）

1. 列出本次所有产物：源码、测试、文档、报告、图片、表格、导出文件、演示。
2. 按 `contract.md §3` 的路由表分类：代码 / 用户要打开的 artifact / 内部证据。
3. 选出 **1–3 个**用户会打开或拿走的东西；其余在正文链接。
4. 决定：`present` 或「无独立交付文件」。
5. 把决定写进 `team-out/delivery-report.md` 的「交付面」段。

**不要**把 `team-out/review.md`、`test-report.md`、`handoff-*.md`、任务板截图当 artifact；它们是证据，正文链接即可。

## 2. `present` 的正确用法

- Lead 在**收尾轮**调用，一次 1–3 个文件；成员不调用。
- 文件必须存在且在工作区内；路径用相对工作区的路径。
- 交付卡片只在本轮结束后出现；卡片是入口，不是完成徽章。
- 已 `present` 的文件，正文仍要写一句「交付物：`<path>`」，方便无卡片环境阅读。
- 不 `present` 时，正文写「本次无独立交付文件」，并说明改动看哪里（改动卡片 / PR / 正文链接）。

### 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 每个文件都 `present` | 卡片噪声，用户不知道看哪个 | 只放 1–3 个用户要打开的 |
| `present` 源码 diff | 与改动卡片重复 | 源码交给改动卡片/PR |
| 把 `team-out` 报告当 artifact | 用户拿到内部工作记录 | 只有正式交付报告才 present |
| 没 artifact 也硬 `present` | 空卡片/凑数 | 写「本次无独立交付文件」 |
| 正文只写文件链接 | 不产生交付卡片 | 需要卡片就调用 `present`；不需要就声明 |

## 3. 交付报告模板

写入 `team-out/delivery-report.md`（证据文件，不默认 `present`）：

```markdown
# 交付报告：<任务名>

## 改了什么
- <文件>：<改动要点>

## 为什么
<关联任务、问题或需求>

## 怎么验证
- 命令：<命令> → 结果：<通过/失败数>
- 手工验证：<步骤与结果>

## 采用的上游结论
- <结论>（L2）→ 核实方式：<回溯的文件:行号 / 命令> → 结果：<成立 / 冲突>

## 风险与未覆盖
- 已验证：<...>
- 未验证：<...>
- 假设：<...>

## 回滚
<git revert / 配置回退 / 数据回滚步骤>

## 交付面
- artifact：<路径 / 无>
- 展示面：<交付卡片 / 改动卡片 / 正文>
- present：<已调用 / 未调用；原因>
- 最终声明：<交付物：... / 本次无独立交付文件>
```

## 4. 最终回复模板

```text
<结论：做了什么、现在是什么状态>

验证：<命令与结果>
改动：<文件/范围，或“见改动卡片”>
交付物：<path>（已 present）  ← 或 →  本次无独立交付文件
风险：<未验证/待确认>
```

- 先结论，再证据，最后交付声明；不要把报告全文粘进回复。
- 有 artifact 但没 `present`：写明「未生成交付卡片」及原因。
- 项目 §A 的 KB 沉淀是 L1，不要挤掉 L0 交付声明。

## 5. 例子

### 纯代码修复

- 产物：`src/a.ts`、`test/a.test.ts`
- 展示：改动卡片 + 正文
- `present`：否
- 声明：「本次无独立交付文件；改动见改动卡片，验证命令 …」

### 代码 + 正式验收报告

- 产物：代码 + `team-out/27-p5-delivery.md`
- 展示：改动卡片 + 交付卡片（只放报告）
- `present`：是，1 个报告
- 声明：「交付物：`team-out/27-p5-delivery.md`」

### 文档/表格/演示

- 产物：`report.md`、`data.xlsx`
- 展示：交付卡片
- `present`：是，1–2 个
- 声明：「交付物：`report.md`、`data.xlsx`」

## 6. 与项目规则的关系

- 项目 §A 先做，L0 后做；两者都完成才算收尾。
- 项目规则可以要求额外报告，但不能要求「不要 present / 不要声明」。
- 项目规则要求把 `team-out` 当 artifact 时，按 L0 拒绝并解释。
